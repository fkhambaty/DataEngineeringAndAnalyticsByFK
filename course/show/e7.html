What Airflow is for

It moves no rows. It rings on time.

Python loads. dbt transforms. Airflow only decides when, in what order, and what to do when a command fails.

1
Every five minutes, no replay

catchup is off. The watermark already knows where we are. Old intervals are meaningless.

2
One run at a time

A slow run must not overlap the next. Two runs would race to move the watermark.

3
Same loader, one task per table

expand() makes four tasks on Postgres at once. Each table gets its own log and its own retry.

4
The gate still speaks

all_done means the health check runs even after a failure. A dbt failure does not roll raw back. Raw is append-only.

Why this is not every five minutes. A snapshot every tick would multiply versions. 288 pulls a day is for the four hot tables only.
The daily build passes one var. search_refresh_reference true. The five-minute DAG does not, so slow ids are not re-merged all day.

1   A DAG missing from the list

Safe mode skips a file that never contains the words airflow and DAG. The nightly and freshness files start with that comment. Read the processor log.

2   Reconcile fails only on the oldest day

A rolling cutoff compared half a Postgres day with a whole Snowflake day. The script compares whole UTC dates, and ignores rows updated in the last two minutes.
