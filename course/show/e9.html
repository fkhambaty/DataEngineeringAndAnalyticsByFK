00_architecture/OPERATIONS_RUNBOOK.md

A hot table goes quiet.

1
Is the source up?

Postgres reachable, and did the Airflow extract task fail? Read LOAD_LOG.error_message.

2
Leave the watermark

Retry the failed mapped task. Raw is append-only and staging dedupes, so a retry is safe.

3
One missed window

Trigger meridian_bounded_replay with one table, since, and until. Forward progress stays put.

4
Then prove it

dbt build --selector microbatch, then assert_pipeline_health. A green DAG with a red V_PLATFORM_STATUS row is still an incident.

02:00

First page of the runbook. One incident, start to finish.

meridian_bounded_replay

Re-copy one window. Watermark stays.

$python pg_to_snowflake.py --tables core.transactions --since 2026-09-01T00:00:00Z --until 2026-09-02T00:00:00Z
PARAMS

table · since · until

The DAG default table is core.transactions. since and until are UTC timestamps. Schedule is none. The selector is microbatch or daily.

SAFE

Append, then dedupe

The copy lands again in raw. Staging keeps one row per key. The normal watermark does not move.

THEN

Rebuild consumers

dbt build --selector microbatch, or daily if the param says so. catchup stays off.

Airflow catchup would invent a second set of windows and race the watermark. Replay is the one window you name.
