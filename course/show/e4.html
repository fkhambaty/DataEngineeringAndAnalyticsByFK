Why this script exists

Snowflake cannot see the laptop. Python carries the rows.

dbt only sends SQL to Snowflake. Something else has to read Postgres and hand files across. That something is pg_to_snowflake.py.

Three things this script is not

The courier is a small Python job.

dbt sends SQL

It builds tables from data that is already in Snowflake. It never opens Postgres.

ref() and source() only

A connector logs in

snowflake.connector is the cable. It is not a job that copies the bank.

login, then you send SQL

Already inside

no path back to the laptop

extract_table()

Stream rows. One file per chunk.

pg_to_snowflake.py · extract_table()
with pg_conn.cursor(name=f"ingest_{table.name}_{batch_id[:8]}") as cur:
    cur.itersize = INGEST.chunk_rows
    while True:
        rows = cur.fetchmany(INGEST.chunk_rows)
        if not rows:
            break
        df = pd.DataFrame(rows, columns=[c.name for c in cur.description])
        df["_extracted_at"] = _naive(extracted_at)
        df["_batch_id"] = batch_id
        chunk_max = df[table.cursor_column].max()
        max_cursor = max(max_cursor, chunk_max) if max_cursor else chunk_max
        path = out_dir / f"{table.name}_{batch_id}_{part:05d}.parquet"
        pq.write_table(arrow_table, path, compression="snappy")

Eight uploads at once

Parquet is already compressed, so AUTO_COMPRESS is false. The stage is PG_STAGE.

2
$1 is the whole row

It lands in record, a VARIANT. Typing waits for dbt. _loaded_at fills itself.

3
All of the batch, or none

One bad file aborts the statement. PURGE deletes the staged files after success.

4
MERGE the bookmark

Only after COPY. A replay with --since and --until loads rows and leaves the mark alone.

If the script dies in the middle

Run it again. Same final answer.

BEFORE COPY

The bookmark has not moved. Raw has nothing from this run. The next run reads the same window and tries again.

03_stages_raw_tables_control.sql

One view for the whole courier.

V_PIPELINE_HEALTH
SELECT w.table_name, w.last_watermark,
  timestampdiff('minute', w.last_watermark, current_timestamp()) AS minutes_behind_source,
  l.status AS last_status, l.rows_extracted AS last_rows,
  timestampdiff('second', l.started_at, l.finished_at) AS last_duration_s
FROM MERIDIAN_RAW.CONTROL.WATERMARKS w
LEFT JOIN MERIDIAN_RAW.CONTROL.LOAD_LOG l
  ON l.table_name = w.table_name AND l.batch_id = w.last_batch_id
minutes_behind

How far the bookmark sits behind the clock.

last_status

SUCCESS, NO_CHANGES, or FAILED. Replay uses its own names.

last_rows

rows_extracted on that batch. Zero is a quiet window.

last_duration_s

finished_at minus started_at, in seconds.
