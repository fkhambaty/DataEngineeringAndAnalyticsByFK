Why the shape pays off

Every question: filter, then add up.

Monthly spend by branch
select d.year_month, b.branch_name,
       sum(f.amount_reporting) as spend_usd
from   fct_transactions f
join   dim_date   d on d.date_key   = f.date_key
join   dim_branch b on b.branch_key = f.branch_key
group by 1, 2
order by 1, 3 desc;

Slowly changing dimension · type 2

Same customer. Two eras.

The customer moved from RETAIL to PREMIUM in August. A payment from March must still say RETAIL. So we keep both versions, each valid for a window of time.

Written once, used everywhere

One macro guards every join.

macros/helpers.sql
{% macro scd2_match(ts_expr, dim_alias) -%}
  {{ ts_expr }} >= {{ dim_alias }}.valid_from
  and {{ ts_expr }} < {{ dim_alias }}.valid_to
{%- endmacro %}
models/marts/core/fct_transactions.sql
left join dim_account da on da.account_id = t.account_id
  and {{ scd2_match('t.transaction_ts', 'da') }}
1
Start included, end excluded

valid_from ≤ time < valid_to. Two windows never overlap, so one match.

2
Used on every SCD2 join

Customer and account both carry versions. Both joins call the macro.

3
Why 9999-12-31, not NULL

The current version still has an end date, so the same simple range check works for every row.
